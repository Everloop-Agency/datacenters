DATA-CENTERS CLOUDFLARE WORKER SETUP
=====================================

This folder contains the COMPLETE Worker source:

    cloudflare/worker.js

Copy that entire file into the existing Cloudflare Worker:

    data-centers

Then deploy it.

NO REAL SECRET VALUES ARE INCLUDED IN THIS GITHUB PROJECT.


1. REQUIRED CLOUDFLARE VARIABLES / SECRETS
-------------------------------------------

Open:
Cloudflare -> Workers & Pages -> data-centers -> Settings -> Variables and Secrets

Configure the following values.

Required for this frontend:

ALLOWED_ORIGINS
  Example values, comma-separated:
  http://localhost:8000,https://everloop-agency.github.io

CESIUM_ION_TOKEN
  Type: SECRET
  Use the dedicated restricted BROWSER token created in Cesium ion.
  Recommended restrictions in Cesium ion:
    - assets:read only
    - selected assets only
    - allowed URLs limited to your GitHub Pages site and localhost
  Do NOT use a high-privilege Cesium account token.

HAZARD_API_URL
  Normal variable:
  https://api.weathertrade.net/api/customer/get_data/hazards

HAZARD_API_KEY
  Type: SECRET
  Use the same WeatherTradeNet API key used by the Cotton Risk Management app.

HAZARD_API_EMAIL
  Prefer type: SECRET
  Use the same WeatherTradeNet API email/account value used by the Cotton Risk Management app.

GEOCODER_URL
  Only needed for postal-address search.

ASSET_API_BASE
  Needed only by the legacy /api/3d-assets route.
  The current frontend primarily obtains the restricted Cesium token from /api/cesium-token.

The following legacy variables are only needed if those legacy Worker routes are still used elsewhere:

BASEMAP_TILE_URL
BASEMAP_CREDIT
FLOOD_DATASET_URL
FIRE_DATASET_A_URL
FIRE_DATASET_B_URL
FIRE_DATASET_C_URL

The current datacenters frontend loads flood and wildfire datasets directly from their public providers.


2. ROUTES PROVIDED BY worker.js
--------------------------------

/api/hazards
  Proxies WeatherTradeNet physical-climate risk scores.
  HAZARD_API_KEY and HAZARD_API_EMAIL stay server-side.

/api/cesium-token
  Returns the restricted Cesium browser token to the frontend.
  The token is kept out of GitHub, but because Cesium runs in the browser,
  a visitor can still see this restricted token in browser network tools.
  That is why this token must be low-privilege and URL/asset restricted.

/api/geocode
  Optional address search.

/api/3d-assets
  Legacy Cesium asset endpoint route retained for compatibility.

/api/map-config
/api/diagnostics
/api/flood
/api/fire
  Legacy/compatibility routes retained in the Worker.


3. TEST AFTER DEPLOYING
------------------------

Open your datacenters website first so the browser sends an allowed Origin.
Then in Chrome DevTools -> Console test:

fetch("https://data-centers.everloop.workers.dev/api/hazards?lat=31.995&lon=-106.363")
  .then(async r => ({ status: r.status, body: await r.text() }))
  .then(console.log)

Expected:
  status: 200
  response JSON contains a "hazards" object

Test Cesium token route:

fetch("https://data-centers.everloop.workers.dev/api/cesium-token")
  .then(async r => ({ status: r.status, body: await r.text() }))
  .then(console.log)

Expected:
  status: 200

Do NOT post the returned token publicly.

Common errors:
  403 = current website origin is not in ALLOWED_ORIGINS
  503 = one or more required Worker variables/secrets are missing
  502 on /api/hazards = WeatherTradeNet upstream rejected or failed


4. GITHUB SAFETY
----------------

The repository .gitignore excludes:
  .env / .env.*
  .dev.vars / .dev.vars.*
  Wrangler local state/config
  common key/certificate/credential files

Before pushing, run:

  git status

  git ls-files | grep -E '(\.env|\.dev\.vars|wrangler|credentials|secrets)'

  git grep -n -i -E 'api[_-]?key|secret|password|bearer|private[_-]?key'

Seeing variable NAMES such as HAZARD_API_KEY is normal.
A real secret VALUE must never appear in the repository.

If a real key/token was ever pushed previously, rotate/revoke it even after removing it from Git history.
